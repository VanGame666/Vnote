# 通信模式与协议总结笔记

## 一、 网络寻址基础
无论何种应用层协议，在网络层建立连接的方式只有两种：
1.  **直接寻址**：通过 `IP地址 + 端口号` 直接访问。
2.  **域名寻址**：通过 `域名` 访问，由 **DNS** 系统将其解析为对应的 IP 地址。

## 二、 核心通信模式对比
以下模式定义了数据交换的逻辑规则，与底层寻址方式无关。

| 模式          | 核心描述                                                   | 典型类比                     | 常见协议/场景               |
| :------------ | :--------------------------------------------------------- | :-------------------------- | :------------------------ |
| **请求-响应** | 客户端发送请求，服务端处理并返回响应，同步等待。                | 打电话问问题。                | HTTP、RPC、API调用。        |
| **发布-订阅** | 发布者向主题发送消息，订阅者接收感兴趣主题的消息，双方解耦。     | 杂志订阅/电台广播。           | MQTT、Kafka、系统事件总线。 |
| **单向通知**  | 发送方只发出消息，不期待、也不需要接收方回应。                  | 广播警报、发射信号弹。         | UDP广播、Syslog。          |
| **轮询**      | 客户端定期主动向服务器发起查询，以获取新数据。                  | 不断刷新网页查看更新。         | 检查任务状态、定时拉取邮件。 |
| **长轮询**    | 客户端发起请求，服务器仅在数据就绪时返回响应，实现“服务器推送”。 | 等电梯，门开了（有数据）才响。 | Web即时消息、在线协作工具。  |
| **点对点**    | 网络中的节点地位平等，可以直接相互通信和交换资源。              | 面对面交谈、文件互传。         | P2P下载（BT）、区块链网络。 |

## 三、 设备直连协议的特殊性
蓝牙/USB等协议位于更底层，解决“设备如何发现并直接连接”的问题，其通信模式通常是内嵌的、混合的。

| 协议 | 核心模式 | 关键特点 |
| :--- | :--- | :--- |
| **蓝牙** | **混合模式** | 1. **经典蓝牙**：常用于**点对点**音频/数据传输。<br>2. **低功耗蓝牙**：基于 **“客户端-服务器”**架构，同时使用**请求-响应**和**发布-订阅**（通知）模式，是物联网核心。 |
| **USB** | **主机轮询（主从架构）** | 所有通信必须由**主机**发起并轮询，**外设**只能被动响应。这是一种严格的、由主机集中控制的**请求-响应**模式。 |

## 四、 关键概念辨析
- **HTTP vs. MQTT**：两者寻址方式相同。区别在于，HTTP连接**Web服务器**，使用“请求-响应”模式；MQTT连接**消息代理**，使用“发布-订阅”模式进行异步通信。
- **通信模式 vs. 传输协议**：通信模式（如发布-订阅）是**逻辑模型**；传输协议（如TCP/IP、蓝牙、USB）是**实现载体**，可以在其上承载一种或多种逻辑模式。
- **网络协议 vs. 设备直连协议**：
    - 网络协议（HTTP/MQTT）假设设备已接入**IP网络**，解决“在网络上如何对话”。
    - 设备直连协议（蓝牙/USB）解决“如何建立最初的物理/链路层连接”，之后再在其上运行各种对话逻辑。
