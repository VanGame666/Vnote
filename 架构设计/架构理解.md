# 架构风格理解笔记：分层、模块、事件驱动、状态机

## 1. 核心比喻（用户的理解）

|   架构/模式   |     比喻      |                                     核心职责                                      |
| ------------ | ------------- | -------------------------------------------------------------------------------- |
| **分层架构** | 搭建良好的地基 | 定义系统的垂直结构（上层依赖下层），规定代码的物理组织和依赖方向，为上层架构提供稳定基础。 |
| **模块架构** | 制造好用的工具 | 水平拆分功能单元，每个模块高内聚、低耦合，可复用、可替换，如同专用工具。                 |
| **事件驱动** | 高效的完成任务 | 在分层和模块的基础上，通过异步、非阻塞的调度机制，高效处理并发任务。                     |
| **状态机**   | 管理复杂的流程 | 专门处理有状态、有流程的逻辑，将复杂条件判断转化为清晰的状态转移。                       |

---

## 2. 它们不是互斥的，而是协同工作

在实际系统中，这四者**组合使用**，各自负责不同层面的问题：

- **分层架构**：提供整体骨架（如应用层/服务层/HAL/驱动）。
- **模块化**：在每一层内部实现高内聚的功能单元（如WiFi模块、传感器模块）。
- **事件驱动**：作为调度机制，连接模块、分发事件（如按键事件分发到UI或状态机）。
- **状态机**：在具体模块内部管理复杂状态（如设备工作模式管理）。

---

## 3. 工厂比喻（整体视角）

将系统比作一个工厂：

- **分层架构** = 工厂的**厂房结构**（原料区、加工区、质检区、包装区）  
  规定了物料流向和职责分区，保障生产流程有序。

- **模块化** = 工厂的**专用机器**（焊接机、组装机、检测仪）  
  每台机器完成特定功能，可以独立更换升级。

- **事件驱动** = 工厂的**传送带 + 调度系统**  
  当某个工序完成后自动触发下一个工序，物料不等待、不阻塞，实现高效流转。

- **状态机** = 工厂的**流程控制程序**  
  根据当前订单状态（接单→排产→生产→质检→发货）决定下一步动作，管理复杂生产流程。

---

## 4. 总结

- 这四种架构风格/模式解决了不同层面的问题，分别对应**结构组织、功能拆分、任务调度、流程管理**。
- 优秀的系统设计往往**组合使用**它们：用分层搭建框架，用模块化组织功能，用事件驱动提升并发效率，用状态机简化复杂业务逻辑。
- 理解各自的定位，有助于在设计中做出合理的取舍与组合。
